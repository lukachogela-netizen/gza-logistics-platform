# რეალური სქრინშოტების ჩეკლისტი

ეს დოკუმენტი არის სახელმძღვანელო. აქ ჩამოთვლილი სქრინშოტები ჯერ არ არის გადაღებული და უნდა შეიქმნას აპლიკაციის რეალურად გაშვების შემდეგ.

## UI/UX და რესპონსიულობა

1. **Desktop (1440px):** Chrome-ში გახსენი `http://localhost:5173`, გააფართოვე ფანჯარა 1440px-ზე და გადაიღე ძირითადი გვერდი Header/Sidebar/მარშრუტის ბარათებით.
2. **Mobile (375px):** Chrome DevTools → Toggle Device Toolbar → Custom 375×812. გადაიღე კადრი დახურული მენიუთი და მეორე კადრი გახსნილი hamburger მენიუთი; უნდა ჩანდეს ერთსვეტიანი მარშრუტების სია.
3. **Tablet (768px):** Device Toolbar-ზე დააყენე 768px; შეამოწმე Sidebar-ის overlay და ბარათების განლაგება.

## ფუნქციური ქცევა

4. **Form validation:** შესული მძღოლის/კომპანიის ანგარიშით გახსენი „ახალი მარშრუტი“, ცარიელი ველებით დააჭირე შენახვას; გადაიღე ვალიდაციის შეტყობინებები.
5. **CRUD:** შექმენი მარშრუტი, შეცვალე, შემდეგ წაშალე. არ გამოიყენო seeded route-ის edit/delete თუ ის სხვა მფლობელს ეკუთვნის.
6. **Booking / Store:** დაჯავშნე რეისი და გადაიღე კადრი, სადაც Header counter და `/bookings` გვერდის სია განახლებულია.
7. **Backend:** ტერმინალში აჩვენე Express API გაშვებული; ბრაუზერში გახსენი `http://localhost:4000/api/health`. შემდეგ ჩაიტარე register → login → route create → booking.
8. **Overbooking:** სატესტო გარემოში შექმენი/გამოიყენე რეისი ერთი ადგილით, სცადე მეორე დაჯავშნა და ჩაიწერე, რომ API აბრუნებს `409`-ს. არ გააყალბო წარმატებული პასუხის სქრინი.
9. **Offline fallback:** პირველ რიგში ჩატვირთე API-ის რეალური მონაცემები, შემდეგ გათიშე backend ან DevTools Network-ში აირჩიე Offline. განაახლე გვერდი და გადაიღე cache/demo banner.
10. **Error Boundary / debugger:** მხოლოდ სატესტო გარემოში გამოიწვიე React render error ან breakpoint-ი; Sources-ში აჩვენე Call Stack, Scope და Watch. შემდეგ დააჭირე Retry-ს და მოაშორე ხელოვნური შეცდომა.

## კროს-ბრაუზერული ტესტი

11. გაიმეორე ძირითადი ნაკადები მეორე ბრაუზერში (Firefox ან Edge). ჩაიწერე თარიღი, ბრაუზერის ვერსია და დაფიქსირებული ბაგები/შედეგები.
