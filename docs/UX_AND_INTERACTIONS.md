# UX/UI ანალიზი და ინტერაქციების დაგეგმვა

## 1. მთავარი User Flow — მარშრუტის მოძიება და დაჯავშნა

სცენარი: სტუმარი პოულობს ქალაქებს შორის რეისს და ჯავშნის ერთ ადგილს.

1. **მთავარი გვერდი:** სტუმარი ხედავს საძიებო ველსა და მარშრუტების ბარათებს.
2. **ძიება:** სტუმარი აკრეფს ქალაქს ან მძღოლის სახელს. UI განაახლებს ფილტრაციას 350ms პაუზის შემდეგ.
3. **შედეგის არჩევა:** ბარათში სტუმარი ამოწმებს თარიღს, დროს, ფასს და თავისუფალ ადგილებს.
4. **დაჯავშნა:** სტუმარი აჭერს „დაჯავშნა“ ღილაკს. ღილაკი გადადის loading რეჟიმში; ერთსა და იმავე მარშრუტზე სწრაფი განმეორებითი დაჭერა იბლოკება.
5. **დადასტურება:** თუ API მუშაობს, სერვერი SQLite ტრანზაქციით ამოწმებს და ამცირებს თავისუფალ ადგილებს, ხოლო პასუხი Zustand Store-ს აახლებს. API-ის ქსელური/5xx შეცდომისას ჯავშანი მხოლოდ ბრაუზერის demo/cache მდგომარეობაში ინახება და შესაბამისი banner ჩანს.
6. **ჯავშნების ნახვა:** მომხმარებელი გადადის „ჩემი ჯავშნები“ გვერდზე; ავტორიზებულისთვის სერვერი უბრუნებს საკუთარ ჯავშნებს, ხოლო offline demo რეჟიმში გამოიყენება ამ ბრაუზერის ჩანაწერები.

**მიზნობრივი ინტერაქციები:** საძიებო ველში აკრეფა (350ms debounce), ბარათზე „დაჯავშნა“ (ერთი ადგილი) ან დეტალურ გვერდზე გადასვლა და ადგილების რაოდენობის არჩევა. UI-ში JWT რეგისტრაცია/შესვლა არსებობს; მისი სერვერული მუშაობა ხელით smoke test-ით უნდა დადასტურდეს.

## 4. Responsive State Analysis

- **375px მობილური:** sidebar დამალულია off-canvas რეჟიმში და იხსნება hamburger ღილაკით; სტატისტიკა 2-სვეტიან კომპაქტურ ბადედ, მარშრუტების ბარათები 1 სვეტად; მოდალი ქვემოდან სრულ სიგანეზე იხსნება.
- **768px პლანშეტი:** sidebar hamburger ღილაკით იმართება; მარშრუტების ბადე 2 სვეტად; საძიებო ველი ფილტრისგან განცალკევებულად ადაპტირდება.
- **1440px desktop:** sidebar მუდმივად ჩანს; მთავარი ნაწილი იკავებს დარჩენილ სივრცეს; მარშრუტები 3 ან მეტ სვეტად ლაგდება ხელმისაწვდომ სიგანეზე დაყრდნობით.

რეალური 375px/1440px screenshots ჯერ უნდა გადაიღოს სტუდენტმა გაშვებული აპლიკაციიდან Chrome DevTools-ის Device Toolbar-ით.

## 5. ინტერაქციის ანალიზი — 3+ micro-interactions

### A. მარშრუტის ბარათის hover
- **Trigger:** მაუსი გადადის RouteCard-ზე.
- **Rules:** ვიზუალური მდგომარეობა იცვლება მცირე მასშტაბით, business state არ იცვლება.
- **Feedback:** ბარათი ოდნავ აიწევს და ჩრდილი გაძლიერდება (`transform: translateY`, `box-shadow`).
- **Loops / Modes:** transient hover; მაუსის მოცილებით საწყის მდგომარეობას უბრუნდება.

### B. Live search debounce
- **Trigger:** მომხმარებელი საძიებო ველში აკრეფს.
- **Rules:** `useDebounce` 350ms-ით აყოვნებს query-ის საბოლოო მნიშვნელობას; ფილტრაცია შემდეგ სრულდება.
- **Feedback:** სია იცვლება; ცარიელი შედეგისას ჩნდება „მარშრუტი ვერ მოიძებნა“.
- **Loops / Modes:** ყველა შეყვანა ტაიმერს თავიდან იწყებს; პაუზის შემდეგ ძიება სრულდება.

### C. ჯავშნის დადასტურება
- **Trigger:** „დაჯავშნა“ ღილაკზე დაჭერა.
- **Rules:** მარშრუტის მოქმედება იკეტება, loader ჩნდება; API ხელმისაწვდომობისას სერვერი transaction-ში ხელახლა ამოწმებს ხელმისაწვდომობას და ინახავს ჯავშანს, ხოლო fallback-ში მონაცემი ლოკალურად ინახება.
- **Feedback:** disabled/loading button და success/error toast.
- **Loops / Modes:** idle → pending → success/error → idle; ადგილები 0-მდე ჩამოსვლისას ღილაკი disabled ხდება.

### D. Modal open/close
- **Trigger:** Add New/Edit-ზე დაჭერა, Close-ზე ან Overlay-ზე დაჭერა, Escape.
- **Rules:** ფორმა `createPortal`-ით body-ში რენდერდება, focus გადადის პირველ ველზე, body scroll იბლოკება.
- **Feedback:** dim overlay, მოდალის fade/translate, შეცდომები ველებთან.
- **Loops / Modes:** closed/open/saving/error; წარმატებული submit-ის შემდეგ იხურება.

## 6. Loading / Empty / Validation / Error states

- **Loading:** card skeleton-ები.
- **Empty:** „მარშრუტი ვერ მოიძებნა. შეცვალე საძიებო სიტყვა ან გაასუფთავე ფილტრები.“
- **Validation:** შესაბამის ველთან კონკრეტული შეცდომა; `aria-invalid` და `aria-describedby`.
- **Success:** toast „ახალი მარშრუტი დაემატა“ ან „ჯავშანი წარმატებით შეიქმნა“.
- **API fallback:** ყვითელი banner „ლოკალური დემო რეჟიმი“.
- **Runtime error:** Error Boundary Fallback UI და Retry ღილაკი.

## 7. Accessibility / Mobile-first

- ყველა მოქმედება native `<button>`-ებითაა წარმოდგენილი; ლინკები ნავიგაციისთვის.
- ფორმის ყველა input-ს აქვს label; ვალიდაციის ტექსტი დაკავშირებულია ველთან.
- `:focus-visible` აშკარა outline-ით ჩანს.
- hamburger ღილაკს აქვს `aria-expanded` და `aria-label`.
- modal-ს აქვს `role="dialog"`, `aria-modal="true"`, title/description და Escape close.
- `prefers-reduced-motion` ამცირებს მოძრაობის ეფექტებს.
- ღილაკის არჩევა Tab-ით და Enter/Space-ით შესაძლებელია native HTML ქცევის გამო.
